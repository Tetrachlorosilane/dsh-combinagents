## 2. 已修复发现

### A-1（High）普通 fork 继承了源组合 membership

**位置**：`src/manager.js` `resolveSession()`。

旧实现只检查 `summary.nativeParentSessionId`，而 `summaryOf()` 对任何
`header.parentSession` 都填这个字段。DSH 的普通 fork 会保留源 session id
作为 `parentSession`，但没有 `origin: 'subagent'`，它是一棵新的 native tree。

**影响**：

- `resolveSession(fork)` 返回源组合，`/state?sessionId=fork` 显示源组合；
- `create(fork)` 不创建新组合，而是 sync 源组合；
- `cloneTree(fork)` / `bud` 以 fork 为入口时实际克隆源组合；
- `addNode` 把 fork 当作源组合成员，可能走跨组合移动分支；
- 与 AGENTS.md “Ordinary forks are new roots” 明确冲突。

实机 `/sessions` 中 154 个 top-level 会话里有 14 个带 `parentSession`，
说明这不是纯理论路径。

**修复**：只有 `summary.source === 'subagent'` 时才沿 native parent 链上溯；
普通 fork 直接返回 `null`。新增
`ordinary forks lead a new composition instead of inheriting the source`。

### A-2（High）跨组合移动丢失 grant，显式 deny 变成默认 allow

**位置**：`src/manager.js` `moveAcrossExclusive()`。

同组合 reparent 走 `migrateParentGrants`，但跨组合 `add-node` 的移动分支：

- 只对新的边界 edge 调 `grantManualConnection`，新 edge id 没有旧 grant，
  因此默认写成 `allowMessage:true`；
- 内部 edge id 虽然保留，但 target policy 里没有对应 grant，读出来是 deny。

**影响**：一个原本被显式禁止消息的节点，移动到另一组合后自动获得消息权限；
一个 delegation 子树原本 `allowMessage/allowInterrupt:true` 的内部边被悄悄降为 deny。
这是授权状态在结构编辑中被重置/提权。

**修复**：

- 移动前读取 source/target policy；
- 保留子树内部 edge 的 grant；
- 新边界 edge 继承旧入边 grant；旧入边存在但没有 grant 时写显式 deny，
  防止 `grantManualConnection` 默认 allow；
- 旧入边不存在（source root 作为新子节点）才使用手工连接默认值；
- policy 写失败时保持 fail-closed 并记录 warning。

新增 `preserves edge grants when a subtree moves across compositions`，
同时覆盖“auto-mirrored deny 不被移动默认值覆盖”。

### A-3（High）`create` / `addNode` 的 owner 检查在锁外

**位置**：`src/manager.js` `create()`、`addNodeExclusive()`。

`create`/`addNode` 先在锁外 `resolveSession`，再进 per-root / global lock。
如果另一 profile 在两步之间把同一 session 加入组合，旧代码不会再检查：

- `create` 看到 `store.get(root)` 为空，直接创建第二个组合；
- `addNodeExclusive` 只检查 target graph，直接把 session 加进 target；
- `indexComposition` 检测到冲突只会 warn 并拒绝覆盖，导致 target graph 有节点
  但 membership 仍指向另一个 root，后续 `/state` 与工具解析不一致。

**修复**：在持锁后重新 `resolveSession`：

- `create` 发现已有其他 owner 时返回该 owner 的记录（随后正常 sync），不再建新记录；
- `addNodeExclusive` 发现其他 owner 时返回 409 `SESSION_ALREADY_COMPOSED`，
  客户端重试会走移动分支。

新增 `create and add-node re-check membership under the composition lock`，
用延迟 store 在锁等待窗口注入另一组合，旧代码会失败。

### A-4（High）store reload 采纳了快照中不存在的 revision

**位置**：`src/store.js` `open()` / `refresh()`。

旧流程在 `refresh()` 中 close 旧 domain、`await open()`，然后
`revision = readRevision()`。若另一 profile 在 `open()` 的 `loadAll()` 之后、
这次 `readRevision()` 之前写入，本进程会把新 token 当作已加载：
下一次 `refresh()` 看到 `disk === revision`，永久跳过这次写入，直到又发生一次写入。

**修复**：`open()` 只保留它在 `loadAll()` 之前观察到的 revision；
`refresh()` 不再在 open 后覆盖。新增
`does not adopt a revision that the reopened snapshot does not contain`：
模拟快照后写入，第一次 refresh 后第二次 refresh 必须重新打开并读到第三条记录。

### A-5（High）reload 失败后仍报告 durable，并读到空内存 / 静默丢写

**位置**：`src/store.js` `refresh()`。

旧实现先 `opened = null`、close 旧 domain，再 `open()`；`open()` 失败只 log，
`mode` 仍是 `durable`。之后：

- `tableOf()` 拿到 `null`，所有读走空的 `memory` Map；
- `mode` 仍显示 `durable`，UI 不显示内存告警；
- `put` 走内存并报告成功，重启/重连后丢失。

**修复**：

- reload 前把已打开 domain 的各表快照到 `memory`；
- 旧 domain 关闭后 open 失败，设置 `mode='memory'`、`degraded=true`；
- 读继续使用快照（组合不会从 UI 消失）；
- 所有 composition/policy/task/clone 写通过 `assertWritable()` fail-closed；
- `withMutationLock` 在 degraded 或 refresh 失败时拒绝执行，避免用旧快照覆盖
  另一 profile 的新状态；错误信息明确要求重启 Host。

新增 `keeps a readable snapshot and fails closed when a reload fails`。
注意：这是**降级到只读进程内快照直到重启**，不是自动重连；自动重连需要把
memory 中未持久化的写与重新打开的 domain 合并，当前不做，避免静默覆盖。

### A-6（Medium）`sync-native` 重复创建 external/one-shot 占位

**位置**：`src/manager.js` `syncNativeTree()`、`autoAttach()`、`addExternal()`。

external 节点没有 `sessionId`，旧 `existing` 只按 `node.sessionId === entry.id`
匹配，永远匹配不到。连续 sync：

```text
after create   2 nodes / 1 external
after sync 1   3 nodes / 2 external
after sync 2   4 nodes / 3 external
```

最终会撞到 `MAX_COMPOSITION_NODES=256`，且每次 sync 的 `addGraphNode` 都做
全图校验，形成无意义增长。

**修复**：

- external 节点 id 改为 `external-<sha256(nativeId) 前 32 hex>` 的稳定 id；
- `syncNativeTree` / `autoAttach` / `addExternal` 都按稳定 id 匹配；
- 兼容旧记录：仅当调用方知道 native id 时，才按
  `nativeParentSessionId + label` 匹配“旧随机 id”占位；两个不同的新稳定 id
  不会因同名而被合并；
- `addExternal` 对同一占位是幂等 no-op；HTTP `/add-external` 转发 `externalId`，
  client 从 `/external` 的 `leaf.externalId` 传入。

新增 `sync-native is idempotent for external placeholders and one-shot leaves`
及 HTTP 层重复 add-external 断言。

### A-7（Medium）审批边界使用不可变 `header.cwd`

**位置**：`src/controls.js` `crossesWorkspace()`、`src/discovery.js` `cwdOf()`。

DSH `SessionHeader.cwd` 是创建时元数据；`workingDirectory.set` 只追加
`working-directory/change` 事件，`workingDirectory.get(session)` 才是当前有效目录。
旧审批比较 `callerSession.header.cwd` / `targetSession.header.cwd`，因此：

- 两个 session 创建时 cwd 相同、之后一个切到别处，审批不会触发；
- composition 详情和 picker 也显示旧 cwd，和 AGENTS “cwd 是 observation”
  的承诺不一致。

**修复**：

- `controls` 新增 `cwdOfSession()`，优先 `workingDirectory.get(session)`，
  缺失时才回退 header；
- `crossesWorkspace` 用有效 cwd 比较；
- `discovery.cwdOf()` 同样优先 live 有效 cwd，persisted 才回退 header。

新增 `cross-workspace approval uses the effective live cwd`，并强化 discovery
测试为“header cwd 与 effective cwd 不同，必须返回 effective”。

### A-8（Medium，性能）冷 corpus 并发重复扫描

**位置**：`src/discovery.js` `list()`。

`corpusCache` 只缓存**结果**，没有 in-flight 合并。冷 cache 过期时，多个 tab 的
`/state` / `/sessions` 同时到达，每个都执行一次 `sessionQuery.listSessions()` +
`summaryOf()`。实机 611 个 session 的 8 并发冷 `/state` 约 **1.94 s wall**，
每个请求 1.77–1.94 s；单发冷读约 256 ms。这是典型的惊群。

**修复**：新增 `corpusInFlight` 单飞 Promise；所有并发调用共享同一次原始
corpus 构建，再各自按 `query` 过滤；`.finally()` 清理，失败不缓存。
新增 `coalesces concurrent cold corpus reads`（3 并发只调用一次）。

### A-9（Low，性能）`sync-native` 对已镜像节点仍读标题日志

**位置**：`src/manager.js` `syncNativeTree()`。

旧实现先对每个 `tree.children` 调 `discovery.describe(entry.id)`，再在锁内判断
是否已存在；16 节点树每次 sync 会重复读 15 个已存在 session（冷读时每个可能
是标题日志折叠）。

**修复**：构建 `knownSessions` / `knownExternal` 集合，已存在节点只 prepared 一个
`nodeInput:null`，在锁内只做 mode 对齐；只有新节点才读标题。新增
`sync-native skips title reads for already mirrored nodes`。

### A-10（Low）clone manager unload 的 dispose 链

**位置**：`src/clone-manager.js` `dispose()`。

`void handle.dispose?.().catch?.(() => {})` 在 `dispose` 返回非 Promise 或
`dispose` 不存在时，会对 `undefined` 访问 `.catch`。改为
`Promise.resolve(handle.dispose?.()).catch(...)` 并 try/catch 同步抛错。

### A-11（High）live 拦截器读取了错误的参数字段

**位置**：`src/controls.js` `intercept()`。

DSH `tools/execute` 的实时 `ToolDispatchExecution` 把解析后的参数放在
`exec.arguments`；`ToolDefinition.execute(args, exec)` 才以第一个参数接收它。
旧拦截器调用 `definition.execute(exec.args, exec)`，live `exec.args` 为
`undefined`：

- `list_agents` 不读参数，仍正常；
- `subagent` / `subagent_fork` 在 `args.provider` 处失败
  `Cannot read properties of undefined (reading 'provider')`；
- `send_message` / `interrupt_agent` 在 `args.agent` 处失败
  `Cannot read properties of undefined (reading 'agent')`；
- `wait_agent` 在 `args.timeout_ms` 处失败。

这正好覆盖了 2026-11-18 审计遗留的“live standard-session 拦截验证”缺口。
测试此前直接调用 `definition.execute(args, ...)`，没有走 live
`tools/execute` 包装，因此没有发现。

**修复**：`intercept()` 使用 `exec.arguments ?? exec.args`（兼容直接调用和
旧 harness），并把 controls 测试改为 live 形状 `arguments`；新增
`interception forwards the live exec.arguments shape to tool bodies`。
实机重启前仍会看到上述错误；2026-11-19 02:xx 重启到端口 64806 后已复测：持久 spawn/fork、`send_message`、`wait_agent` 均通过，详见 `docs/BRIDGE-TEST-2026-11-19.md` 第 6 节。

## 3. 仍存在 / 明确接受的风险

以下项目本轮**未修改**，属于产品决策、低风险加固或需要单独设计：

| 项 | 说明 | 建议 |
|---|---|---|
| SEC-6 | 手工连边默认 `allowMessage:true`；是 2026-11-18 产品决策 | 若要更严格，默认 deny + 显式开启；需产品确认 |
| SEC-8 | 无速率限制；token 持有者可反复 `/state`、`/titles`、`/sync-native`、`/clone-tree` | 在 Node handler 加每路由/每 token 的简单令牌桶；clone 已有单飞和 120 s 上限 |
| SEC-9 | 预认证 401/403/413 响应缺少 `nosniff`/CORP（API 正常响应已有） | 复用统一 `json()` 头 |
| SEC-10 | relay 信封与审批 reason 使用节点 label；控制字符已清理，但 bidi/同名仍可视觉冒充 | 信封加 `senderSessionId` 已存在；可显示短 id 或 native name 优先 |
| SEC-11 | loopback 被当作信任边界；本机进程或本地代理/隧道可读 `/bootstrap` token | Host/Origin 只防浏览器 rebinding；本机威胁需 OS ACL / per-profile secret |
| SEC-12 | clone root 不复制源 permission preset，子级继承 clone root 的策略；方向通常更保守，但不是源策略快照 | 若产品要求精确复制，作为单独 audited policy 写入 |
| X-10 | composed `subagent` 的 fallback 参数没有 `agent_preset`，provider capability 只校验 route | 按原生 schema 补齐；显式校验 reasoning effort/provider 能力 |
| 跨 profile task/clone | task/clone-only 写入不发布 `.revision`，任务板跨 profile 可能滞后；2026-11-18 审计已记录 | 若要求任务板强收敛，对 putTask/deleteTask/putClone 也 publish revision（会触发 domain reopen，需评估成本） |
| audit archive | active audit 裁剪到 5000，archive 永不裁剪；每次 domain open 会 `loadAll` 所有表 | 给 archive 设定保留窗口/分片；避免长期磁盘与 open 成本 |
| `/titles` | 10 个持久会话冷读约 **2.1 s**，20 个约 1.5 s（前 10 已缓存） | 已限制 20 个/60 s TTL/单飞；可考虑只显示 id 后异步补标题，或 DSH 侧批量优化 |
| `/sessions` | 611 个 session 时响应约 **239 KB**，冷 471 ms；client 只渲染前 200 | 服务端分页/字段裁剪；当前 localhost 可接受 |
| mutation lock | `.mutation.lock` 30 s 无更新会被视为 stale；极端慢盘上的长 mutation 可能被另一进程越过 | 心跳 touch mtime，或按 pid 存活判断 |
| move 的 side tables | 图移动已加锁/补偿，但 task/policy 迁移仍在图写之后；失败会留下“图已移动、task 未迁移” | 域支持跨表事务前，明确失败恢复或补偿 |
| client 轮询 | tab 3 s、chip 5 s；慢响应可能晚于新响应覆盖状态 | 加请求序号/AbortController；错误退避 |
| fork 显示 | `summaryOf` 仍把普通 fork 的 `header.parentSession` 填进 `nativeParentSessionId` 供显示 | membership 已修复；若 UI 文案要求严格，可区分 `headerParent` 与 `nativeParent` |
| `GET /grants` `/tasks` | 需要 rootSessionId，member id 返回 404；client 使用 `/state` 返回的 root | 可让服务端 resolve member，减少调用方约定 |
